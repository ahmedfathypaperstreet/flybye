# FlyBye — Shared Backend (single source of truth)

Both apps (`flybye-webapp`, `flybye-app`) share ONE Supabase project:
**`pngjuliouszzhylkimsd`**. This folder is the canonical source for the backend.

```
supabase/
├── config.toml            # project ref + edge-function settings
├── migrations/            # canonical schema (apply via db push or paste)
│   └── 20260816000000_unified_schema.sql
├── apply_fresh.sql        # schema + airport seed WITH a destructive reset preamble
│                          #   (use only to wipe & rebuild an empty/dev project)
├── seed/
│   └── airports_seed.sql  # 50 airports
└── functions/
    ├── airport-pois/      # terminal POIs via OpenStreetMap Overpass (both apps)
    └── flight-lookup/     # optional flight auto-fill (needs AVIATIONSTACK_KEY)
```

## Apply the schema
- Fresh/dev project: paste `apply_fresh.sql` into the SQL Editor (it drops & recreates), OR
- Migrations: `supabase db push` (uses `migrations/`).
- Then: **Auth → URL Configuration → Redirect URLs** add `flybye://reset-password` + your web origin.

## Deploy edge functions (run from THIS repo root)
Use `./sb` instead of `supabase` — it pins the CLI to the FlyBye project and
the account that owns it, whatever account `supabase login` is on.
One-time: `cp supabase/.deploy.env.example supabase/.deploy.env` and paste an
access token from the owning account (supabase.com → Account → Access Tokens).
```
./sb projects list                                 # sanity check: FlyBye's account
./sb secrets set AVIATIONSTACK_KEY=<key>           # for flight-lookup
./sb functions deploy airport-pois
./sb functions deploy flight-lookup
```
`airport-pois` needs no secrets — Supabase injects `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY`.
